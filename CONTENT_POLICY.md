# Rules Content Editorial Policy

## Objective

Teach people how a tabletop roleplaying system feels and functions without replacing the publisher’s rulebook or copying protected expression.

## Content schema

Every system guide records:

- system ID and public display name
- edition and rules baseline
- publisher
- license status
- player fundamentals
- Game Master fundamentals
- original-content design guidance
- official source links
- required attribution or trademark disclaimer
- prohibited content categories
- last legal and rules review date

## Writing rules

1. Explain mechanics in original language.
2. Use examples created for this site.
3. Quote only when an exact legal notice is required.
4. Link to official rules for exact procedures and edge cases.
5. Distinguish open-content rules from commentary-only systems.
6. Mark edition-specific content on every card and page.
7. Never merge same-named rules across editions without a documented conversion.
8. Treat “complete guide” as complete orientation, not a replacement rulebook.

## Accuracy workflow

1. Research official publisher sources and current reference documents.
2. Record the source version and publication date.
3. Draft the guide from the source, not from memory.
4. Review numerical claims and timing rules separately.
5. Add a regression test for IDs, required sections, source links, and legal fields.
6. Recheck after errata, license updates, or new editions.

## Release gate

A system page cannot be marked production-ready until:

- the mechanics review is complete
- the license review is complete
- accessibility checks pass
- links resolve
- the page includes player and GM paths
- no protected art, logos, or trade dress are present
